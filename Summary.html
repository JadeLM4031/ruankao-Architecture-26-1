四大核心概念

概念 说明

六层模型（案例必背）

层级 名称 功能说明
1 数据层 底层数据结构，包括区块（区块头+区块体）、链式结构（前块哈希）、哈希函数（如SHA-256）、默克尔树（交易摘要）
2 网络层 P2P点对点网络，节点发现与通信，交易广播和区块传播机制，Gossip协议
3 共识层 让分布式节点对账本达成一致的算法：PoW（工作量证明）、PoS（权益证明）、DPoS（委托权益证明）、PBFT（实用拜占庭容错）
4 激励层 经济激励机制，发行代币/积分，奖励出块节点，鼓励诚实行为，惩罚恶意行为
5 合约层 智能合约的部署和执行环境，脚本代码、虚拟机（如EVM），实现业务逻辑自动化
6 应用层 面向用户的DApp（去中心化应用），如数字货币、供应链溯源、数字身份、NFT、DeFi
六层速记：数 网 共 激 合 应（数据层→网络层→共识层→激励层→合约层→应用层）

智能合约详解（案例300字答题模板）

智能合约是部署在区块链上的可自动执行的程序代码，由以太坊首次提出并实现。它以"如果-那么"的逻辑形式定义交易规则，当预设条件被满足时，合约自动触发执行，无需第三方中介干预。

核心特征：
（1）自动执行：条件满足即触发，无需人工干预；
（2）不可篡改：部署后代码无法修改，运行结果确定；
（3）透明公开：代码在链上可验证、可审计；
（4）去信任：不依赖第三方，由代码逻辑保证执行。

开发语言：Solidity（以太坊）、Move（Diem）等。
运行环境：EVM（以太坊虚拟机）等链上虚拟机。
应用场景：数字资产交易、供应链自动结算、保险自动理赔、DeFi借贷协议。

区块链工作流程（案例必背）

  1. 用户发起交易：用户通过钱包客户端创建一笔交易，用私钥签名
  2. 交易广播：交易通过P2P网络广播到全网节点
  3. 节点验证：各节点收到交易后验证签名有效性、余额是否充足、格式是否合法
  4. 打包进区块：矿工/验证节点将验证通过的交易打包成候选区块
  5. 共识竞争：节点通过共识机制（如PoW算力竞争、PoS权益投票）竞争出块权
  6. 区块广播与验证：获胜节点将新区块广播到全网，其他节点验证区块合法性
  7. 追加到链上：验证通过后，新区块追加到区块链末尾，交易被确认
  8. 全网同步：所有节点更新本地账本副本，达成一致性状态
流程速记：发起 → 广播 → 验证 → 打包 → 共识 → 上链 → 同步

共识机制对比

PoW（工作量证明）
算力竞争出块
✅ 安全性高
❌ 耗能大、速度慢
代表：比特币
PoS（权益证明）
持币量决定出块权

安全风险

  • 51%攻击：控制超过半数算力可篡改交易
  • 智能合约漏洞：代码漏洞导致资金损失（如DAO事件）
  • 私钥丢失：无法找回，资产永久丢失

📄LRU / FIFO / OPT 页面置换

LRU 手算方法

维护列表：左边=最近使用的，右边=最久没用的。命中→移到最左；缺页→淘汰最右，新页加最左。

三种算法对比

算法 淘汰策略 Belady异常
OPT 淘汰将来最久不用的（向后看） 不会
LRU 淘汰过去最近最久未用的（向前看） 不会
FIFO 淘汰最早进入的 可能
Belady异常 = 增加页框数反而缺页率上升。只有FIFO可能出现。LRU和OPT是栈式算法，不会。

缺页率公式

缺页率 = 缺页次数 / 总访问次数

快速判断技巧

  • 前N次访问（N=页框数）必为缺页（初始为空）
  • 刚被淘汰的页面如果马上又被访问，一定缺页
  • 序列中有连续重复的页号 → 命中机会多

🔄PV 操作

基本规则

P(S)：S=S-1，若S<0则阻塞等待  |  V(S)：S=S+1，若有等待进程则唤醒
P = 申请等待  |  V = 释放通知

生产者-消费者

缓冲区容量N。empty=N, full=0, mutex=1：

生产者：P(empty) → P(mutex) → 写 → V(mutex) → V(full)
消费者：P(full) → P(mutex) → 读 → V(mutex) → V(empty)
P的顺序不能反（先P(empty)再P(mutex)，否则死锁）。V的顺序无所谓。N=1时可省略mutex。

多读者-写者

读者：P(mutex); rc++; if(rc==1)P(rw); V(mutex); 读; P(mutex); rc--; if(rc==0)V(rw); V(mutex)
写者：P(rw); 写; V(rw)

前趋同步

P1先完成：V(S)  |  P2后开始：P(S)  |  信号量S=0

做题三问

  1. 谁等谁？ → 先完成的V，后开始的P
  2. 有没有互斥？ → 共享资源需要mutex
  3. 信号量初始值？ → 一般题目会给出

⚡流水线计算

三个核心公式

时钟周期：Δt = max(各段时间)
总时间：T = (级数k + 指令数n - 1) × Δt
吞吐率：TP = n / T  |  加速比：S = 不用流水线时间 / T

计算示例

4级流水线，各段2ns/3ns/2ns/2ns，100条指令：

  • Δt = max(2,3,2,2) = 3ns
  • T = (4+100-1)×3 = 103×3 = 309ns
  • TP = 100/309 ns⁻¹
  • 不用流水线：每条9ns×100=900ns，S=900/309≈2.91

气泡（Stall）

实际时间 = 理想时间 + m×(n-1)×Δt（m=每条指令插入的气泡数）

死锁资源计算

m ≥ n×(X-1) + 1

m=资源总数，n=进程数，X=每个进程最多需要的资源数

含义：最坏情况每个进程各拿(X-1)个（差1个就能完成），再留至少1个给某个进程先完成释放。

CV = EV - AC（成本偏差）>0=节约
SV = EV - PV（进度偏差）>0=超前
CPI = EV / AC（成本绩效指数）>1=节约
SPI = EV / PV（进度绩效指数）>1=超前
EV永远是分子！"偏差"用减法，"指数"用除法

预测公式

BAC = 完工总预算
EAC = BAC / CPI（典型偏差时）
ETC = EAC - AC（还需花多少）
VAC = BAC - EAC（完工偏差）

🧪白盒测试 · 逻辑覆盖

六种覆盖强度排序（从弱到强）

语句覆盖 < 判定覆盖 < 条件覆盖 < 判定/条件覆盖 < 条件组合覆盖 < 路径覆盖

逐一详解

覆盖类型要求说明
语句覆盖每条语句至少执行一次最弱，只管"跑过"，连分支都可能没覆盖全
判定覆盖
（分支覆盖）		每个判定的真假分支至少执行一次覆盖了分支，但不管条件内部的各个子条件
条件覆盖每个条件的真假至少取一次管到每个子条件，但组合情况不一定覆盖
判定/条件覆盖同时满足判定覆盖和条件覆盖既覆盖分支又覆盖每个条件，但条件组合不一定全
条件组合覆盖所有条件的真假组合至少出现一次最强（除路径覆盖外），用例数最多
路径覆盖覆盖程序中所有可能的执行路径理论上最强，但路径数可能爆炸（循环导致无限路径）

快速判断技巧

  • 题目问"最弱的覆盖" → 语句覆盖
  • 题目问"保证每个条件真假都取到" → 条件覆盖
  • 题目问"所有条件组合都要覆盖" → 条件组合覆盖
  • 题目问"覆盖所有可能执行路径" → 路径覆盖
  • 条件组合覆盖的用例数 = 2^n（n=条件个数），如2个条件→4个用例
条件覆盖 ≠ 判定覆盖。条件覆盖管每个子条件的真假，但可能出现：每个条件都取过真假，但判定结果只取了真没取假。所以二者独立，判定/条件覆盖是同时满足两者。

适配器：事后补救，让不兼容的接口能一起工作

稳定性辨析（高频考点）

选择排序不稳定：例 [5, 8, 5, 2, 9]，第一趟选最小值2与第一个5交换，两个5的相对顺序改变。
快速排序不稳定：partition过程中相等元素可能被交换到不同侧。
堆排序不稳定：堆调整过程中相等元素的相对位置可能改变。
简单记忆：O(n log n)的四个算法中，只有归并排序是稳定的。

🔍各算法核心要点

冒泡排序

相邻元素两两比较，每趟把最大值"冒"到末尾。最好O(n)（已有序，一趟就停），最坏O(n²)（逆序）。

选择排序

每趟从剩余元素中选最小值放到已排序末尾。不稳定，比较次数始终为n(n-1)/2，与初始顺序无关。

插入排序

将元素插入到已排序序列的正确位置。最好O(n)（已有序），最坏O(n²)（逆序）。小规模数据或基本有序时效率高。

希尔排序

缩小增量的插入排序。先按大间隔分组做插入排序，逐步缩小间隔。平均O(n^1.3)，不稳定。

快速排序

选基准值(pivot)，partition分为左右两部分，递归排序。平均O(n log n)，最坏O(n²)（已有序+选首元素为基准）。空间O(log n)（递归栈）。

快排最坏情况：数组已有序+选第一个元素为基准→退化为O(n²)。优化：三数取中法选基准。

归并排序

分治法：拆成两半分别排序，再合并。时间始终O(n log n)（最好最坏都一样），空间O(n)（需要辅助数组）。唯一稳定的O(n log n)排序。

堆排序

建大顶堆+反复取堆顶+调整。时间始终O(n log n)，空间O(1)。不稳定。适合大数据量+空间受限场景。

基数排序

按位分配收集：从最低位到最高位，每轮用稳定排序（如计数排序）。时间O(d(n+r))，d=位数，r=基数。适合整数/字符串排序。

🎯排序算法选择（案例题考法）

场景选型

场景推荐算法理由
数据量小（n≤50）插入排序简单、常数因子小、稳定
数据基本有序插入排序最好O(n)
数据量大、随机分布快速排序平均性能最优
需要稳定排序+大数据量归并排序唯一稳定的O(n log n)
空间受限、不要求稳定堆排序O(1)空间
整数且范围不大基数排序/计数排序可达到O(n)
外部排序（数据在磁盘）归并排序顺序访问，适合磁盘IO

易混对比

快速排序 vs 归并排序
快排：先partition再递归，不稳定
归并：先递归再合并，稳定
快排空间O(log n)，归并空间O(n)
堆排序 vs 快速排序
堆排：最坏也是O(n log n)，空间O(1)
快排：最坏O(n²)，但平均更快
堆排不稳定，快排也不稳定

模块B：微服务/SOA（最通用 ⭐）
面向服务架构（SOA）是一种将业务功能划分为独立服务单元的架构方法，通过标准接口和协议实现服务间的松耦合协作。SOA的核心原则包括：服务自治（每个服务独立部署和演进）、接口标准化（统一的通信协议和数据格式）、松耦合（服务间依赖最小化）、服务可重用（通用服务可被多个业务流程调用）。微服务架构是SOA的进一步演进，强调更细粒度的服务拆分、独立的数据存储和去中心化的治理。其关键技术包括服务注册与发现、API网关、负载均衡、熔断降级、分布式配置中心等。相较于传统单体架构，微服务在可扩展性、可维护性和技术栈灵活性方面具有显著优势，但也引入了服务间通信、数据一致性和运维复杂度等新的挑战。
适用方向：微服务、SOA、云原生、系统安全性、自动化测试、大部分通用题目（6个方向）
模块C：大数据处理
大数据处理是指对海量、多源、异构数据进行采集、存储、计算和分析的技术体系。其核心特征可用"5V"概括：Volume（数据量大）、Velocity（处理速度快）、Variety（数据类型多样）、Value（价值密度低）、Veracity（数据真实性）。关键技术包括：分布式存储（如HDFS、对象存储）实现数据的分块冗余存储；分布式计算（如MapReduce、Spark）实现多节点并行处理；流式计算实现实时数据处理。在架构设计中，需要根据数据特征和业务需求选择合适的存储和计算方案，在性能、成本和一致性之间做出权衡。湖仓一体（Lakehouse）是近年的重要发展方向，融合了数据湖的灵活存储和数据仓库的事务一致性，通过统一存储层实现ACID事务支持和Schema管理。
适用方向：大数据处理、湖仓一体、AI/智能化、数据库设计（4个方向）
模块A：分布式系统（备用）
分布式系统是由多台通过网络互联、协同完成任务的计算机节点组成的系统，对外呈现统一的逻辑整体。其核心特征包括：节点自治性（各节点独立运行）、操作透明性（用户无需感知数据分布）、资源共享（跨节点的资源访问）。分布式系统面临三大挑战：一是性能挑战，网络通信延迟和数据分布导致响应时间增加，需通过缓存、并行计算和负载均衡优化；二是可用性挑战，节点故障可能导致服务中断，需通过冗余部署和故障检测保障；三是一致性挑战，CAP定理指出一致性、可用性和分区容忍性三者不可兼得，需根据业务场景在强一致性和最终一致性之间权衡。
模块E：系统可靠性（备用）
系统可靠性是指系统在规定条件下和规定时间内完成功能的能力。核心指标包括：MTTF（平均无故障时间）、MTTR（平均修复时间）、可用性=MTBF/(MTBF+MTTR)。提升可靠性的主要策略包括：冗余设计（多副本部署消除单点故障）、故障检测（心跳机制、健康检查）、故障恢复（自动转移、熔断降级、限流）、容错设计（重试机制、补偿事务、幂等性保障）。可靠性需要在成本和可用性之间权衡——更高的可靠性意味着更多的冗余资源和更复杂的运维。

故事1：点云解析性能瓶颈（万能 ⭐）
开发初期，单节点解析10GB点云文件需约2小时，远超用户期望的30分钟。我分析后发现瓶颈在单线程串行处理和频繁磁盘IO。我决定采用两个优化策略：一是引入并行计算框架，将点云按空间区域分块分配至4个节点同时解析；二是引入内存缓存减少重复IO。优化后解析时间缩短至25分钟，满足性能要求。这让我认识到架构设计必须以实际性能数据为依据，而非凭经验假设。

故事2：服务间数据不一致（万能 ⭐）
上线初期偶尔出现点云解析完成但派发服务未收到通知的情况，排查发现是消息队列高负载时消息丢失。我采取两个措施：一是消息队列开启持久化和消费确认机制；二是引入补偿任务定时扫描未同步数据并重新派发。实施后数据丢失率从0.3%降至0，任务调度成功率从98%提升至99.5%。这让我认识到分布式系统中不能假设任何通信可靠，必须设计容错和补偿机制。

故事3：微服务拆分粒度争议（备用）
架构评审中团队对"图像回传"和"AI缺陷识别"是否合并产生分歧。我最终决定拆分，理由是AI模型迭代频率远高于图像回传模块，拆分后可独立升级；且未来可能接入多种AI模型，拆分后扩展更灵活。上线后AI模块3个月内迭代了4个版本而图像回传服务保持稳定，验证了这一决策的正确性。
故事4：安全性与性能的权衡（备用）
电力公司要求所有数据传输加密，但全量加密数十GB点云数据会导致传输时间增加约40%。我分析后发现点云原始数据不包含敏感信息，真正敏感的是解析后的杆塔位置。因此采用分层加密策略——原始数据不加密（内网环境），结构化结果TLS加密，敏感数据AES-256加密存储。既满足安全要求，又将性能影响控制在5%以内。

合理使用（不构成侵权）

以下可不经许可、不付报酬（但需指明作者）：
① 个人学习、研究或欣赏
② 课堂教学或科学研究（少量复制）
③ 国家机关执行公务
④ 新闻报道中不可避免地引用
⑤ 为介绍/评论某一作品而适当引用
⑥ 免费表演（未收费也未付报酬）
⑦ 翻译成少数民族语言文字在国内出版

情形结果理由
